# ProjectPermit Rescue Target Saturation Rule — 2026-08-28

## Purpose

ProjectPermit is at **50/100, PAUSE / RE-SCOPE**. The bottleneck is no longer finding another renovation marketplace that appears superficially compatible. The bottleneck is obtaining external evidence that can change the commercial decision.

This rule prevents static target discovery from becoming an endless substitute for E2/E3/E4/E5 evidence.

It applies to rescue/falsification research only. It does not change the canonical Go/No-Go score by itself.

---

## Current saturation point

The current top upstream operator set already spans materially different structures:

1. **SoumissionRénovation / RenoQuotes** — large Quebec province-wide aggregation route.
2. **Oolong Media / Soumissions Maison** — verified multi-funnel/operator aggregation route with current-family-controlled sites and central data/triage evidence.
3. **GoSoumissions** — independent Quebec operator with internal request analysis/filtering before contractor invitations.
4. **RenovationFind** — independent Canada-wide concierge qualification + internal fit assessment + smart matching route spanning four current ProjectPermit cities.

These four are sufficient to test whether the upstream lead/quote-operator thesis exists across more than one organization and workflow shape.

Adding another ordinary renovation marketplace with the same public evidence pattern is now low-value.

---

## Default rule: no fifth look-alike marketplace

A new marketplace / quote platform / contractor-referral target should **not** enter the top rescue set merely because it has:

- many contractors;
- many historical projects;
- a renovation category page;
- a quote form;
- city coverage;
- a public contact address;
- generic AI/automation claims;
- or a plausible place where a permit check could theoretically run.

Those signals are already represented in the existing target set.

A fifth or later look-alike platform is rejected by default unless it contributes a materially new evidence surface.

---

## Admission rule for a new upstream operator target

A new operator can displace or join the current top set only if at least one **primary admission condition** is met and the evidence is stronger than the closest existing route.

### Primary admission conditions

#### A. Publicly bounded current-project denominator

The operator publishes a recent, clearly defined unique project/request denominator that can be mapped substantially to current ProjectPermit families and jurisdictions.

Historical cumulative counts, contractor counts and downstream contractor-invitation copies do not qualify.

#### B. Stronger pre-routing insertion evidence

The operator publicly documents a real pre-routing decision stage where staff or automation already assess regulatory/permit/feasibility facts, not merely generic lead qualification.

#### C. Stronger integration surface

The operator exposes a current public API, webhook, CRM enrichment interface, white-label interface or another verified central integration surface that could accept one permit-enrichment integration across meaningful traffic.

#### D. Representative data access path

The operator publicly offers or directly commits access to recent chronological anonymized project records sufficient for an E3-style replay, rather than only marketing aggregates.

#### E. Economic commitment surface

The operator publicly exposes or directly offers a paid enrichment/partner/API procurement path sufficiently concrete to test price/resource commitment.

#### F. Structurally different buyer class

The target represents a materially different upstream buyer class not already covered — for example a property/insurance/lender workflow with repeated permit-applicability decisions — and has a credible high-frequency insertion point.

---

## Evidence types that always outrank adding another marketplace

When any of the following is available, it takes priority over new target discovery:

1. a substantive human reply from an existing target;
2. a bounded recent unique-project denominator;
3. a representative chronological project sample;
4. observed shadow/external calls;
5. price acceptance, paid pilot or engineering/security/procurement commitment;
6. an explicit external-buy vs internal-build answer;
7. a neutral representative incidence dataset or association survey;
8. a newly delivered exact competitor with the same pre-application applicability contract;
9. a safety-relevant representative benchmark that can falsify the engine.

Static website research must yield to these evidence types immediately.

---

## Replacement, not accumulation

If a new target is materially stronger than an existing top route, prefer **replacement/re-ranking** rather than allowing the priority list to grow indefinitely.

Examples:

- a Canada-wide operator with a documented central webhook and recent unique project count can replace a weaker email-only platform;
- an operator that confirms permit applicability is never checked before routing should be downgraded/closed rather than kept indefinitely because its website looks relevant;
- an unreachable platform with inconsistent public data should not retain priority over a reachable operator with a comparable workflow.

The goal is a small set of high-information experiments, not a large CRM list.

---

## Outreach saturation rule

Do not send near-duplicate same-day questions to multiple contacts within the same operator/network merely to increase reply probability.

For an already-contacted operator:

- delivery failure may justify a verified alternate route;
- a forwarding/routing reply may justify the specifically recommended next contact;
- otherwise, additional contact should add a new evidence question or reach a clearly different decision-maker;
- same-day silence is not negative evidence and does not justify contact multiplication.

Bounce/non-delivery must remain separate from market silence.

---

## Current research allocation

Until new evidence appears, effort should be allocated in this order:

1. **Process substantive replies** from existing targets.
2. **Convert a cooperative operator into the bounded operator rescue protocol**: complete-month aggregate + >=20 recent chronological cases + integration topology + material-effect measurement.
3. **Run shadow E4 only after the mechanical and evidence gates pass.**
4. **Test E5 economics/build-vs-buy** only with a real operator willing to commit price/resources.
5. **Continue exact-competitor / neutral-data falsification** only when it is materially new.
6. Add another upstream marketplace only under the admission rule above.

---

## Score consequence

**No score change. Canonical status remains 50/100, PAUSE / RE-SCOPE.**

Saturation is not evidence that demand exists. It means the public-target-discovery phase has produced enough candidate routes that additional look-alike discovery has diminishing information value.

The next score-moving evidence must come from behavior, bounded workflow data, representative cases, real integration preference/usage, economic commitment, or a stronger falsifying competitor.

## Bottom line

ProjectPermit no longer needs more plausible marketplace names.

It needs one of the existing plausible routes to reveal whether the permit-applicability problem is **frequent, unresolved, fact-sufficient, materially useful and worth buying instead of building**.
