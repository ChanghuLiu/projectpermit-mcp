# External Validation Stop Clock — 2026-08-28

Purpose: prevent outreach activity from being mistaken for market evidence. The commercial scorecard has a serious stop signal at **20 qualified external conversations with no bounded repeated upstream permit-applicability workflow**. This file defines what counts toward that clock.

## What counts as a qualified conversation

Count **one** only when a real human at a relevant contractor/platform/association/consulting organization responds with enough context to address at least one of these boundaries:

1. where permit applicability is decided in the workflow;
2. whether it is already known before Request/Assessment/Estimate/Quote;
3. whether the organization has or does not have a bounded denominator/timeframe;
4. whether they would build the logic internally vs buy/use an external capability;
5. whether they can provide representative historical cases;
6. whether they would commit integration resources or pay.

Do **not** count:

- a cold email sent;
- no reply;
- delivery success/no bounce;
- autoresponder/ticket acknowledgement;
- support routing with no workflow/data answer;
- AI support response;
- marketplace/directory listing;
- public website claims by themselves;
- internal CI/API calls;
- synthetic benchmarks.

## Stop rule

When the count reaches 20 qualified conversations, perform a mandatory score review.

If all 20 still show:

- no bounded current-family upstream workflow;
- no representative E3 sample;
- no repeated external usage;
- no credible build-vs-buy preference for the external capability;

then the default action is to move ProjectPermit below the current continuation threshold and **stop new product investment** unless there is a strong contrary E4/E5 signal.

The same review should happen earlier if a stronger falsifier appears, for example:

- multiple software buyers explicitly say they would build a narrow local checker internally;
- an existing competitor confirms a low-friction API that adequately covers the target workflow and price point;
- representative E3 shows unacceptable false `LIKELY_NOT_REQUIRED` risk;
- production usage remains one-off/discovery rather than repeated workflow after credible distribution exposure.

## Current operating rule

Until the clock or a stronger falsifier triggers:
