# Oolong / Soumissions Maison Operator Aggregation Route — 2026-08-28

## Purpose

The Quebec rescue has mostly been evaluated one marketplace or one contractor-software product at a time.

That can understate a different distribution structure:

> one operator may own or centrally manage many quote-comparison funnels, so one commercial/integration relationship could aggregate candidate ProjectPermit traffic across multiple narrow renovation niches.

This note tests that hypothesis for **Oolong Media Inc. / the Soumissions Maison-style network**.

This is **public structural evidence only**. It is not E2 volume evidence, E4 usage, E5 willingness to pay, or proof that one API endpoint exists across all sites.

## 4. Evidence of centralization — what is proven and what is not

### Proven publicly

Across multiple verified sites:

- Oolong Media Inc. is named as owner or data collector/controller;
- Oolong collects and transfers quote-request information to partners;
- multiple sites use `admin@soumissionsmaison.com` for database changes;
- current Oolong operations remain focused on generating and selling leads / quote requests;
- Oolong historically described operating 50+ comparison sites that generated thousands of forms per month.

This is enough to say:

> **an operator-level multi-funnel distribution route is real and worth testing.**

### Not proven

Public evidence does **not** establish that:

- all forms write to one physical database;
- all sites share one CRM tenant;
- one webhook/API can access all funnels;
- every site is currently active;
- every Oolong-owned site can legally/operationally share data with a new enrichment provider;
- Oolong wants permit applicability enriched at the lead-routing stage;
- the current-family subset reaches ProjectPermit's >=500/month rescue threshold;
- the current-family leads have enough decision facts;
- permit applicability is unresolved often enough to matter;
- the signal changes routing or conversion;
- Oolong would buy rather than build the logic.

Do not convert central legal/data identity into a fictional public API.

Oolong published a 2025 article describing a `top renovation client` example with approximately:

- **3,700 quote requests**;
- **75% conversion**;
- **C$35 fixed cost per request**;
- about **C$130,000 annual spend**;
- over **C$1.5M revenue generated**.

Source:

- `https://oolongmedia.ca/comment-obtenir-clients-sans-depenser-publicite/`

Treat this strictly as a vendor-presented case study, not independently audited E2/E5 evidence.

The arithmetic is nevertheless useful structural context:

- `3,700 × C$35 ≈ C$129,500`, consistent with the stated annual spend;
- if 3,700 represents one year, it is about 308 requests/month for that one partner;
- partner-delivered lead count is not the same as unique platform submissions because a lead may be distributed to multiple partners.

Therefore this case **cannot** be added to the current-family market denominator.

It does strengthen one economic question for Oolong specifically:

> can a permit-applicability signal measurably improve the value/routing of a fixed-price renovation lead enough to exceed the incremental call + integration cost?

## 6. Why this route matters more than another isolated marketplace

If every niche marketplace required a separate commercial and technical integration, partner-specific integration cost `I` could dominate early economics.

A verified multi-funnel operator changes that structure:

`one operator relationship -> multiple current-family funnels -> larger N -> lower I/N`

That can improve the external API case **without** requiring ProjectPermit to add jurisdictions or features.

But there is an opposing effect:

- a centralized operator with enough volume also has more incentive and engineering leverage to internalize permit logic;
- Oolong's public operational model includes lead generation, CRM/automation, and internal integration capability;
- therefore aggregation improves distribution economics **and simultaneously raises build-vs-buy pressure**.

The route is only attractive if Oolong confirms both:

1. enough unresolved permit-applicability events exist across its current-family funnels;
2. maintaining municipality-specific deterministic evidence/versioning externally is preferable to building it into the network's own stack.

## 7. Highest-value next operator questions

Do not ask Oolong generic `would this be useful?` questions.

A bounded operator-level response should ideally answer:

### Volume

For the most recent complete month, across Oolong-controlled Quebec funnels that map to current ProjectPermit families:

- window/door;
- kitchen/bath/plumbing;
- basement/interior renovation;
- addition/accessory-structure-like work where applicable;

how many **unique homeowner project requests** were received?

Important: ask for unique project requests, not partner-delivered lead copies.

### Uncertainty

How many of those unique requests still required someone to determine whether a municipal permit was required before routing/sale to partners?

### Fact sufficiency

For a representative recent sample, how often did the existing form/description already contain enough facts for a permit preflight without asking the homeowner another question?

### Integration

Are the relevant funnels centrally available through one CRM/data workflow or would each site need separate integration work?

### Material effect / economics

Would a permit-applicability result alter:

- partner routing;
- lead qualification;
- price/tier;
- manual validation/research;
- rejection/refund/complaint rate;
- or another measurable workflow outcome?

### Build vs buy

Would Oolong prefer:

- an externally maintained municipality-by-municipality deterministic service;
- or adding municipal permit logic into its own CRM/automation stack?
