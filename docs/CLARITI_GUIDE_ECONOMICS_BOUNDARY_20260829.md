# Clariti Guide Public Procurement Economics Boundary — 2026-08-29

## Purpose

Clariti Guide already counts as a major upstream requirements/productization threat in the canonical scorecard. The surviving ProjectPermit thesis is narrower: some private software/agent buyers may prefer a lightweight developer-native external machine contract instead of municipality-oriented Guide deployments or internal logic.

This review tests one tempting rescue assumption:

> `Clariti Guide is probably so expensive/heavy that ProjectPermit's low-cost delivery shape has obvious whitespace.`

Public municipal procurement evidence does **not** support that assumption.

## Current Clariti positioning

Clariti currently describes Guide as:

- a pre-application permitting assistant for governments;
- priced according to population rather than a public fixed self-serve price;
- implemented with Clariti's in-house implementation team;
- deployable for some permit types in a few weeks;
- a fraction of the cost of a full permitting system.

Current product page:

- https://www.claritisoftware.com/products/guide

This confirms a configured municipal implementation model, not an ordinary anonymous developer API purchase.

## Named public procurement anchors

### Stanislaus County, California

Public Board of Supervisors material describes the Camino Guide (now Clariti Guide) as a virtual pre-meeting that asks project questions, uses GIS and automatically returns customized process/fee/timeline information.

The original agreement was reported as:

- **US$25,000 annual cost**;
- **US$10,000 initial implementation**;
- later renewal at **US$26,250 annual cost**.

Source:

- https://www.stancounty.com/bos/agenda/2025/20250225/D01.pdf

### Bakersfield, California

A 2025 City administrative report adding Guide to an existing Clariti environment states:

- **US$50,000 for a one-year Guide subscription**.

The report explicitly ties the purchase to reducing permit/planning clarification calls and improving pre-application efficiency.

Source:

- https://pub-bakersfield.escribemeetings.com/filestream.ashx?DocumentId=12002

### Rochester Hills, Michigan

City Council authorized a Permit Guide + virtual inspection software package from Camino with a contract/blanket purchase order not to exceed **US$30,000** through April 2025.

This package is not directly comparable to Guide-only annual pricing, but it independently confirms that a municipal permit-guide deployment can sit in a tens-of-thousands rather than enterprise-million-dollar procurement band.

Source:

- https://roch.legistar.com/LegislationDetail.aspx?GUID=F105E682-58DA-4D34-BCE0-B8C7818CFD73&ID=5555885&Options=&Search=

## What the public economics do prove

The named examples are sufficient to reject this weak rescue claim:

> `Municipality-grade upstream permit guidance is necessarily too expensive to be a realistic substitute.`

Guide has been bought at public price points around the **tens-of-thousands of US dollars per year / deployment** in named jurisdictions.

That is materially lower-friction economically than a full enterprise permitting replacement and consistent with Clariti's current positioning.

## What they do not prove

These municipal contracts do **not** establish:

- a private-software/API price;
- ordinary third-party access to Guide's determination output;
- per-call economics;
- one machine contract reusable across unrelated private buyers;
- Canadian private software buyer preference;
- willingness to pay for ProjectPermit.

A municipality paying US$25k–50k/year for a configured public-facing Guide is not the same procurement problem as a contractor/PropTech/agent platform buying a lightweight external API.

## Decision impact

**No score change.** Canonical remains **48/100 — PAUSE / RE-SCOPE**.

Clariti Guide has already driven the relevant competitive/defensibility dimensions to zero. Public procurement economics strengthen the existing threat but cannot be double-counted.

The remaining ProjectPermit argument cannot be:

> `Clariti is too expensive.`

It must instead be demonstrated externally as:

> `A private software/agent buyer prefers a low-friction developer-native cross-city machine contract because municipality-oriented Guide deployments, internal local logic and broader platforms do not fit its workflow/economics.`

That buyer-preference claim still has no E2/E4/E5 support. The pending Clariti API-boundary inquiry and private-software conversations are therefore more important than further public Guide pricing research.
