# One Ontario / LandLogic Direct-Integration Requirement Boundary — 2026-08-28

## Purpose

The canonical scorecard already assigns **0/10 competitive headroom** after Parcella / One Ontario closed the remaining obvious external cross-city whitespace. A stronger No-Go trigger remains explicitly separate:

> LandLogic / One Ontario exposes permit-requirement output as an ordinary external machine contract at credible multi-municipality coverage/economics.

This note records stronger current delivery evidence while preserving the final semantic boundary that is still not publicly proven.

## Current delivery is no longer roadmap-only

LandLogic announced on 2026-08-12 that it is **now powering the One Ontario solution** for streamlined development approvals.

Source:

- https://www.landlogic.ai/latest-updates/powering-one-ontario

One Ontario's current owners/developers surface is also live enough for users to try the first version for free. Users can describe a project in plain language; the platform identifies requirements, explains feasibility, checks compliance, prepares applications and guides the approval process.

Source:

- https://www.oneontario.ca/owners-and-developers

This makes One Ontario / Parcella materially stronger than a future-only concept.

## Requirement identification is explicitly part of the platform

One Ontario's earlier pilot description already included a **Requirements Menu** that automatically determines project requirements from:

- project location;
- project characteristics;
- local-authority regulations.

Source:

- https://www.oneontario.ca/latest-updates/one-ontario-is-revolutionizing-the-development-approvals-process

The current 2026 owners/developers surface independently says the platform identifies requirements from a user's project description and provides AI-guided regulatory guidance.

Therefore automated requirement identification itself is not an inferred capability.

## LandLogic is the technology partner for that intelligence layer

One Ontario's 2026-06-10 technology-partner announcement says LandLogic is the first official technology partner for the province-wide AI-enabled permitting platform.

It states that LandLogic's permitting technology includes:

- requirement identification;
- automated code and compliance checking;
- agentic submission and tracking workflows.

It further says many of these capabilities are already being deployed through municipal and industry initiatives across Ontario.

Source:

- https://www.oneontario.ca/latest-updates/landlogic-joins-ai-for-housing

This is materially stronger than a generic property-data partnership.

## Direct integrations are also explicitly part of the architecture

The same One Ontario announcement describes the platform as **scalable intelligence infrastructure**, not traditional permitting software, and says it will support:

- AI-enabled workflows;
- **direct integrations**;
- human-supported processes.

One Ontario's current AI for Housing material likewise describes shared, standardized permitting infrastructure connecting data, workflows and requirements across municipalities.

Sources:

- https://www.oneontario.ca/latest-updates/landlogic-joins-ai-for-housing
- https://www.oneontario.ca/ai-for-housing

Separately, LandLogic publicly offers API integrations, reports APIs, automatic updates, custom branding and conversational-AI integrations for its property/planning intelligence layer.

Source:

- https://www.landlogic.ai/integration

A named production-style external deployment also exists outside permitting: GeoWarehouse / Teranet released an Enhanced Zoning Report developed with LandLogic, showing that LandLogic's external data/integration capability is not merely a mock API page.

Source:

- https://www2.geowarehouse.ca/blog/introducing-the-enhanced-zoning-report-indepth-address-specific-zoning-detail/

That deployment proves external delivery capability but **not permit-requirement API output**.

## Industry-development partner is not buyer acceptance

RESCON joined the AI for Housing Coalition as development partner in June 2026. One Ontario states that RESCON represents builders responsible for more than 70% of Ontario's new homes and will provide housing-delivery guidance to the coalition.

Source:

- https://www.oneontario.ca/latest-updates/rescon-joins-ai-for-housing

This is strong industry relevance and design-partner evidence.

It is **not** evidence that representative software buyers or builders have accepted the current Parcella / One Ontario requirement output as good enough for an operational third-party machine workflow, and it is not E2/E5 for ProjectPermit.

## The remaining one-centimetre semantic gap

The public evidence now separately proves:

1. One Ontario automatically identifies project requirements;
2. LandLogic supplies the technology/intelligence layer;
3. the platform is being deployed, not merely proposed;
4. the architecture supports direct integrations;
5. LandLogic already delivers external APIs/integrations in adjacent property/planning workflows.

What it still does **not** explicitly prove is this exact contract:

`third-party software -> project/address/scope -> programmatic permit-requirements determination`

It would be evidence-unsafe to infer that exact endpoint merely by combining the five facts above.

## Decision rule

### Mandatory score review

Trigger the score review already defined in `docs/GO_NO_GO_SCORECARD.md` if One Ontario / LandLogic confirms or demonstrates that:

- requirement-identification output is available to ordinary third-party software through a direct integration/API;
- the machine contract operates across meaningful maintained Ontario municipality coverage;
- access/economics are credible enough for software buyers rather than being a bespoke consulting engagement.

### No immediate score move

Do not lower the score merely because:

- One Ontario has a live end-user conversational experience;
- LandLogic has APIs for zoning/property intelligence;
- the platform architecture supports generic direct integrations;
- RESCON participates as development partner;
- requirement identification exists internally.

Those facts are already reflected in the current **50/100 PAUSE / RE-SCOPE** score.

## Current conclusion

The competition evidence is now stronger and the unresolved boundary is narrower:

> One Ontario / LandLogic is a delivered requirement-identification platform with direct-integration architecture, but public evidence still stops just short of proving that permit-requirement determination itself is an ordinary externally callable machine contract.

No further broad One Ontario/LandLogic feature research is useful. The next score-moving evidence is the direct semantic confirmation or a public API/integration document that proves the exact contract.
